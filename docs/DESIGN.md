# 视觉与交互规则

这个 App 的"设计"不在好看，在**一眼看懂这张照片为什么被列出来**。所以规则分三块：视觉 token、交互纪律、文案语气。改界面前三块都要过一遍。

### 形态约定

- 卡片：白底 + 14 圆角 + **无阴影**（靠底色对比分层，不用 elevation）。
- 缩略图：正方形裁切（`scaledToFill` + `clipped`），视频右下角带时长角标，选中时蓝色描边 + 右下角勾选。
- 分组卡：组内横排小图，右上角放大入口。
- 列表项：左侧缩略图 78pt，右侧两行（时间 + 元信息），右端为分数或标签。

## 交互纪律

| 规则 | 原因 |
|---|---|
| **点按 = 选中/取消**，**长按 = 进大图** | 选中是高频动作，必须一击完成；进大图是低频且需要退出的动作 |
| 模糊页**列表布局**下点右侧「算清晰」= 永久排除这张 | 这一页的主要诉求是"这张其实挺清晰"，排除比看图更常用。（**网格布局没有这个入口**，是已知缺口，见 `TODO.md`） |
| 分组页**隐藏布局切换按钮** | 分组必须按组看，切成单列会破坏"组"的语义 |
| 选中**跨标签保留** | 用户会在"重复"里选几张，再去"相似"里选几张，最后一起删。切标签丢选中是严重挫败 |
| **> 500 张**的选中/删除先弹确认 | 「全选 2779」后按钮直接变「删除 2779 张」，误触代价太大 |
| 批量删除后给 toast，2.4 秒自动消失 | 需要"已删除 N 张"的确认感，但不能挡住下一步操作 |
| 弹窗 / 大图 / 逐张过**必须 item 驱动**（`sheet(item:)`） | 用 `isPresented` + 并列状态会在首次弹出时拿到旧快照，表现为"第一次点开永远空白" |
| 扫描期间禁止自动锁屏 | 锁屏会挂起 App，掐断解码与 Vision |
| 固定浅色（`preferredColorScheme(.light)`） | 深色下缩略图与卡片对比失衡；这是决定，不是没做 |
| 关键控件带 `accessibilityIdentifier` | 云端 Maestro 用例靠它定位，改名会挂 CI |

## 文案语气

**规则：说人话、给数字、给下一步。**

| 场景 | 反例 | 本项目的写法 |
|---|---|---|
| 权限被拒 | 无法访问相册 | 没有相册访问权限。请到「设置 → 相册整理 → 照片」里打开权限，然后回来重试。 |
| 部分授权 | 权限受限 | 相册权限：仅部分照片（建议改成全部） |
| 删除成功 | 操作成功 | 已删除 12 张 · 30 天内在「最近删除」可恢复 |
| 误判说明 | 该照片模糊度较高 | 清晰度只有 23/100，比相册里大部分照片糊 |
| 风险提示 | 请谨慎操作 | 标记只是暂存，回到列表点红色按钮才会真正删除 |

要求：

1. **第二人称、口语**，不用"用户""您"。
2. 涉及不可逆操作，必须写**恢复路径和时限**。
3. 涉及分数，必须写**它在跟谁比**（"比相册里大部分照片糊"，不是"模糊度 87%"）。
4. 不用"智能""AI 一键""深度优化"这类词。功能就叫它本来的名字。

## 底部 tab 导航（1.4(20) 已实施）

**动机**（不是"像微信好看"，是两个具体问题）：

1. 顶部右上角「空间 / 筛选 / 逐张过」和摘要数字抢位置，12 号字已被压成一行省略号，再加功能没地方放。
2. 顶部横向 chips 已有 13 个，一屏只露 3 个半，后面的要靠横滑，很多用户不知道右边还有。

**实际落地：4 个 tab，但分组和原计划不同**

| Tab | 内容 | 说明 |
|---|---|---|
| **清理**（默认） | 顶部摘要 + 全部 chips + 列表/网格/分组 + 底部操作条 | 主战场，一行未改 |
| **分类** | 九类内容卡片（张数 + 体积），点一下跳回清理并定位到该类 | 原计划是"分类 tab 内再放 9 个二级 chips"，实际做成总览页——多一层 chips 等于把横滑问题搬进 tab |
| **空间** | 原空间看板，从 sheet 改为常驻页 | 少了"打开→关闭" |
| **我的** | 版本号、重新扫描、判定口径说明 | 原计划还想放"导出清单"，实际留在清理页底部——它是对当前结果的操作，不是设置 |

**保留在顶部**：「筛选」（全局条件，不该只在一页生效）、「逐张过」（当前分类的上下文操作）。

### 左右滑不做独立 tab

三条理由，任何一条单独成立就够：

1. **它需要输入**。逐张过的是"当前这个分类里的照片"。做成 tab，进去先看到一个空页让你选分类，多一步。
2. **它是一次性任务**。iOS 惯例把"看完就给结论"的流程做成模态页（相机、编辑、分享都是），做完回列表。tab 是常驻目的地。
3. **它会在 tab 上长期挂一个空态**。tab bar 每一项都该有内容。

### 实现约束（踩过的坑）

- **不能用系统 `TabView`**：它会销毁被切走的页面，`selectedIDs` / 滚动位置 / 筛选条件全丢，而"切分类不丢选中"是明确承诺。改成四页常驻 + `opacity` 切换。
- **`bottomArea` 必须从 `overlay` 改 `safeAreaInset`**：两个都贴底的话，操作条会直接压在 tab bar 上。
- **toast 不能放进 `safeAreaInset`**：它是布局的一部分，出现/消失会把整页内容顶得上下跳。改成挂在按钮区顶部的 `overlay`。
- **Maestro 用例**：改了 5 条（01/02/03/06/08）。tab 的 `accessibilityIdentifier` 用 ASCII（`tab-clean` / `tab-space`），中文标签随时可能改。
