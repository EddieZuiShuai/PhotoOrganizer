# 视觉与交互规则

这个 App 的"设计"不在好看，在**一眼看懂这张照片为什么被列出来**。所以规则分三块：视觉 token、交互纪律、文案语气。改界面前三块都要过一遍。

## 视觉 token

### 字号

| 角色 | 值 | 用法 |
|---|---|---|
| 页面主标题 | 22 semibold | 首页主张、大区块标题 |
| 主按钮 | 17 semibold | 全宽主行动 |
| 分节标题 | 15~16 semibold | 卡片标题、分组名 |
| 正文 | 14~15 | 功能描述、条目主文案 |
| 次要说明 | 13 | 权限状态、辅助提示 |

### 形态约定

- 卡片：白底 + 14 圆角 + **无阴影**（靠底色对比分层，不用 elevation）。
- 缩略图：正方形裁切（`scaledToFill` + `clipped`），视频右下角带时长角标，选中时蓝色描边 + 右下角勾选。
- 分组卡：组内横排小图，右上角放大入口。
- 列表项：左侧缩略图 78pt，右侧两行（时间 + 元信息），右端为分数或标签。

## 交互纪律

| 规则 | 原因 |
|---|---|
| **点按 = 选中/取消**，**长按 = 进大图** | 选中是高频动作，必须一击完成；进大图是低频且需要退出的动作 |
| 模糊页**列表布局**下点右侧「算清晰」= 永久排除这张 | 这一页的主要诉求是"这张其实挺清晰"，排除比看图更常用。（**网格布局没有这个入口**，是已知缺口，见 `TODO.md`） |
| 分组页**隐藏布局切换按钮** | 分组必须按组看，切成单列会破坏"组"的语义 |
| 选中**跨标签保留** | 用户会在"重复"里选几张，再去"相似"里选几张，最后一起删。切标签丢选中是严重挫败 |
| **> 500 张**的选中/删除先弹确认 | 「全选 2779」后按钮直接变「删除 2779 张」，误触代价太大 |
| 批量删除后给 toast，2.4 秒自动消失 | 需要"已删除 N 张"的确认感，但不能挡住下一步操作 |
| 弹窗 / 大图 / 逐张过**必须 item 驱动**（`sheet(item:)`） | 用 `isPresented` + 并列状态会在首次弹出时拿到旧快照，表现为"第一次点开永远空白" |
| 扫描期间禁止自动锁屏 | 锁屏会挂起 App，掐断解码与 Vision |
| 固定浅色（`preferredColorScheme(.light)`） | 深色下缩略图与卡片对比失衡；这是决定，不是没做 |
| 关键控件带 `accessibilityIdentifier` | 云端 Maestro 用例靠它定位，改名会挂 CI |

## 文案语气

**规则：说人话、给数字、给下一步。**

| 场景 | 反例 | 本项目的写法 |
|---|---|---|
| 权限被拒 | 无法访问相册 | 没有相册访问权限。请到「设置 → 相册整理 → 照片」里打开权限，然后回来重试。 |
| 部分授权 | 权限受限 | 相册权限：仅部分照片（建议改成全部） |
| 删除成功 | 操作成功 | 已删除 12 张 · 30 天内在「最近删除」可恢复 |
| 误判说明 | 该照片模糊度较高 | 清晰度只有 23/100，比相册里大部分照片糊 |
| 风险提示 | 请谨慎操作 | 待删是暂存，点「删除 N 张」才真删；不删就带回列表统一处理 |

要求：

1. **第二人称、口语**，不用"用户""您"。
2. 涉及不可逆操作，必须写**恢复路径和时限**。
3. 涉及分数，必须写**它在跟谁比**（"比相册里大部分照片糊"，不是"模糊度 87%"）。
4. 不用"智能""AI 一键""深度优化"这类词。功能就叫它本来的名字。

- 给卡片加阴影、渐变、玻璃拟态。这个 App 的层次靠白卡片 + 灰底。
- 引入深色模式适配（当前是明确不支持）。
- 用 emoji 当分类图标（`ContentCategory.icon` 统一走 SF Symbols）。

## 底部 tab 导航（1.4(20) 已实施）

**动机**（不是"像微信好看"，是两个具体问题）：

1. 顶部右上角「空间 / 筛选 / 逐张过」和摘要数字抢位置，12 号字已被压成一行省略号，再加功能没地方放。
2. 顶部横向 chips 已有 13 个，一屏只露 3 个半，后面的要靠横滑，很多用户不知道右边还有。

**实际落地：4 个 tab，但分组和原计划不同**

| Tab | 内容 | 说明 |
|---|---|---|
| **清理**（默认） | 顶部摘要 + 全部 chips + 列表/网格/分组 + 底部操作条 | 主战场，一行未改 |
| **分类** | 十一类内容卡片（含隐私照片 / 隐私视频 / 视频），点一下**在本 tab 内下钻**到该类列表 | 原计划是"分类 tab 内再放 9 个二级 chips"，实际做成总览页——多一层 chips 等于把横滑问题搬进 tab。1.5 把"点卡片跳清理 tab"改掉，见下。1.5(24) 补了「视频」，分类才真正覆盖全部素材 |
| **空间** | 原空间看板，从 sheet 改为常驻页 | 少了"打开→关闭" |
| **我的** | 版本号、开关、缓存、权限、教程、FAQ、反馈、判定口径说明 | 原计划还想放"导出清单"，1.5(22) 已把导出清单整个移除——分类/空间 tab 已把内容可视化，导出是没人用的文本 dump |

**保留在顶部**：「筛选」（全局条件，不该只在一页生效）。1.5(22) 把顶部「空间」按钮也删了——它和底部「空间」tab 重复；顺手把「筛选」从 11 号小胶囊放大成整颗按钮（原来是它和空间挤在一起、太小了）。

> 1.5 起「逐张过」也从顶部挪到了列表上方的整行入口，见文末。

### 左右滑不做独立 tab

三条理由，任何一条单独成立就够：

1. **它需要输入**。逐张过的是"当前这个分类里的照片"。做成 tab，进去先看到一个空页让你选分类，多一步。
2. **它是一次性任务**。iOS 惯例把"看完就给结论"的流程做成模态页（相机、编辑、分享都是），做完回列表。tab 是常驻目的地。
3. **它会在 tab 上长期挂一个空态**。tab bar 每一项都该有内容。

### 实现约束（踩过的坑）

- **不能用系统 `TabView`**：它会销毁被切走的页面，`selectedIDs` / 滚动位置 / 筛选条件全丢，而"切分类不丢选中"是明确承诺。改成四页常驻 + `opacity` 切换。
- **`bottomArea` 必须从 `overlay` 改 `safeAreaInset`**：两个都贴底的话，操作条会直接压在 tab bar 上。
- **toast 不能放进 `safeAreaInset`**：它是布局的一部分，出现/消失会把整页内容顶得上下跳。改成挂在按钮区顶部的 `overlay`。
- **Maestro 用例**：改了 5 条（01/02/03/06/08）。tab 的 `accessibilityIdentifier` 用 ASCII（`tab-clean` / `tab-space`），中文标签随时可能改。

## 分类卡片：下钻，不跨 tab（1.5 改）

1.4 的行为是：点分类卡片 → `requestedTab = .content(c)` → 跳到**清理** tab。

问题不在跳转本身，在**回不去**：分类 tab 没有被压栈，用户想再挑一类只能手动点回底部 tab，而且清理页的滚动位置、筛选都换了。体验上像是"点了一下，人被扔到别处"。

现在改成：`NavigationStack` + `navigationDestination`，在分类 tab 内推一层 `CategoryDetailView`。

| 决定 | 理由 |
|---|---|
| 用 push 不用 sheet | sheet 是"临时任务，看完关掉"；浏览一整类需要能一直往下滚，还要有返回栈 |
| 不加第五个 tab | 这一页在语义上是「分类」的子页，不是平级栏目 |
| 详情页带完整的选中 / 删除 | 否则用户还得回清理页再找一遍这些照片 |
| 隐私两类在详情页顶部加一行口径说明 | 它们是概率判定，不给解释就会被当成"乱标" |

### 视频为什么不拆「大视频 / 小视频」两张卡（1.5/24）

用户的原话是"视频是不是要拆成两个，一个是大文件视频，一个是小文件视频"。**没这么拆**：

拆了以后一个视频既是"大视频"又是"视频"，**分类轴的互斥性就破了**（每张只能有一个 `category`，破了之后所有统计都会重复计数）。体积是**类内属性**，不是分类。

改成：加一张「视频」卡（让分类覆盖全部素材），进去以后体积作为**筛选**（全部 / ≥100MB / <100MB），默认按体积倒序——"挑大视频"这个真实诉求一样能干，分类轴还干净。

### 补扫时卡片显示百分比，不显示 0（1.5/24）

1.5(23) 的真实事故：用户升级后发现「二维码 0」，以为功能没生效，清缓存重扫十几分钟才看到数字。

问题不在数字错，在 **0 和"还没算"长得一模一样**。现在补扫期间卡片右上角显示 `62%`，副标题写"补扫中…"；扫完才显示真实数量。

### 隐私组的「隐藏」放哪（1.5/24）

| 决定 | 理由 |
|---|---|
| 只放在隐私类 | 普通分类里"隐藏"没有语义，只会增加误触 |
| 分类详情页底部 + 清理页隐私页签底部 | 两个入口都是"已经选中了一批隐私内容"的场景，就近操作 |
| 不进「逐张过」 | 那里是快速连滑，误点一次照片就消失了，代价太大 |
| 必须有「我的 › 已隐藏的照片」找回入口 | 隐藏后 App 里看不见（`includeHiddenAssets = false`），没有找回通道等于永久弄丢 |
| `hiddenIDs` 和 `deletedIDs` 分开记 | 隐藏不释放空间，混进已删除集合会让空间页的「已释放」虚高 |

## 逐张过：从右上角挪到列表上方（1.5 改）

原来是顶部工具栏里一个 11 号字的小胶囊，和「空间」「筛选」挤在一起。1.5 改成列表上方一整行：

```
[✋] 逐张过  128 项            左右滑快速筛 ›
```

**为什么仍不做第五个 tab**（这次是正面评估后的结论）：

1. 它是**对当前列表的动作**，不是目的地。放进 tab 后，用户还得在 tab 里再选一次"过哪一类"，把刚选好的上下文扔掉重来。
2. 张数是这个入口最重要的信息（"过 3 张"和"过 800 张"是两件事），tab 图标放不下数字。
3. tab bar 已经有 4 项，第 5 项会让每项文字被挤到 9 号字以下。

放列表上方而不是底部的理由：底部已经有一条操作条（选中后出现），两个都贴底会互相顶。

## 逐张过：按钮重排 + 批量删除（1.5(22) 改）

原来底部四按钮是「撤销 / 保留 / 标记 / 删除」，「删除」立即删当前这一张。两个问题：

1. **手势和按钮镜像错位**：左滑 = 标记、右滑 = 保留，但按钮里「保留」在左、「标记」在右，正好反过来。
2. **两套删除路径打架**：「标记」是暂存（回列表删）、「删除」是立即删当前张，语义混乱。

现在改成「撤销 / 待删 / 保留 / 删除」：

| 决定 | 理由 |
|---|---|
| 按钮顺序对齐手势（待删在左、保留在右） | 左滑待删、右滑保留，Tinder 式心智，按钮和手势同向 |
| 「标记」改名「待删」+ 图标 `bookmark.fill`→`flag.fill` | bookmark 像"收藏"；「待删」比「标记」更直接，且两个字不破坏对称 |
| 删除改成「批量删所有已标记」 | 和「标记=暂存待删」自洽，动态显示「删除 N 张」、没标时置灰 |
| **去掉「立即删当前张」** | 它会重新引入第二条删除路径；两步（标 → 统一删）比一步安全 |

## 教程页（1.5 新增）

见 `docs/onboarding-spec.md`。这里只记视觉约束：

- 载体 `.sheet` + `.presentationDetents([.large])`，可下滑关闭（`fullScreenCover` 没有下滑手势，不选）；
- 每页三块：动作式标题（22 semibold）/ 假 UI 示意图（白卡，高 220，14 圆角）/ 记忆句（左侧 3pt 蓝竖条 + `#EEF2FC` 浅底）；

- 示意图一律用组件现画，**不截图**：截图改一次字号就全过期。
